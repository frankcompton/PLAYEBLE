## Deploy

Автодеплой настроен на VPS через `.github/workflows/vps.yml`.

Workflow запускается при push в любую ветку и вручную через `workflow_dispatch`.
Он ставит зависимости, собирает проект через `npm run build`, загружает `dist`
на сервер и публикует ветку в отдельную папку.

URL после деплоя:

- `main` -> `http://132.243.19.25/`
- `dev` -> `http://132.243.19.25/dev/`
- `dev-deploy` -> `http://132.243.19.25/dev-deploy/`
- любая другая ветка -> `http://132.243.19.25/<branch-name>/`

В GitHub нужно один раз добавить repository secrets:

- `VPS_HOST`
- `VPS_USER`
- `VPS_PASSWORD`

Для деплоя достаточно закоммитить изменения и запустить:

```bash
npm run deploy
```

Команда пушит текущую ветку и печатает URL деплоя. Если новых коммитов нет, она вручную запускает workflow через `GH_TOKEN`/`GITHUB_TOKEN` с правом запускать Actions. Токен можно положить в локальный файл `.env.local` по примеру `.env.example`.

Локальный деплой напрямую по SSH:

```bash
npm run deploy:ssh
```

Эта команда собирает тот же single HTML пакет, загружает `dist` на VPS через `scp`
и публикует его через `ssh` в папку текущей ветки. Параметры берутся из `.env.local`
или переменных окружения: `VPS_HOST`, `VPS_USER`, `VPS_SSH_KEY_PATH`,
`VPS_PASSWORD`, `VPS_PORT`, `VPS_TARGET_ROOT`, `VPS_CHOWN`. Если есть SSH-ключ,
он используется первым; если используется пароль, нужен установленный `sshpass`;
без ключа и `VPS_PASSWORD` команда работает через обычный интерактивный password prompt.

Handoff-пакет для дизайнера с прямым деплоем:

```bash
npm run handoff:deploy
```

Команда создаёт папку `handoff-deploy/`. Внутри уже есть `.env.local` и SSH-ключ
`.secrets/vps_key`; подключение идёт пользователем `playeble_deploy`. Дизайнер
может отредактировать креатив и запустить:

```bash
npm run deploy
```

Эта команда спросит название проекта для URL и опубликует сборку в
`http://132.243.19.25/<project-name>/`. Текущий `npm run deploy` в основном
репозитории остаётся GitHub Actions деплоем по git-ветке, а `npm run deploy:ssh`
остаётся локальным SSH-деплоем по git-ветке.

## Structure

Редактировать нужно исходники в корне проекта:

- `index.html`
- `style.css`
- `script.js`
- `fx.js`
- `sfx.js`
- `config.js`
- `main.js`
- `build.mjs`
- `assets/`
- `public/assets/pixi.min.js`

`dist/` создается сборкой и вручную не правится.

## What `config.js` controls

`config.js` — это главный файл настроек креатива.

В нем меняются:

- баланс и валюта
- размер сцены
- цвета и визуальная тема
- шрифты
- пути к картинкам и звукам
- символы слотов
- длительности и тайминги
- эффекты и их интенсивность
- стартовый экран
- сценарии спинов
- тексты CTA
- URL оффера

Если нужен рескин, обычно правятся именно эти блоки, а не логика в `script.js`.

## Assets

Все медиа лежат локально, интернет для запуска не нужен:

- картинки и UI: `assets/`
- звук: `assets/sfx/`
- PixiJS: `public/assets/pixi.min.js`

После сборки все нужное попадает в `dist/assets/`.

## Preloader

Preloader уже не чисто визуальный:

- он ждет картинки
- он ждет звуки
- после этого инициализируются FX и игра
- скрывается только когда все готово

## Build

Установка зависимостей:

```bash
npm install
```

Сборка финального пакета:

```bash
npm run build
```

Результат появляется в `dist/`.

## Editing workflow

Если нужно что-то исправить:

1. Меняешь файл в корне проекта
2. Запускаешь `npm run build`
3. Проверяешь `dist/index.html`
4. Отдаешь байерам папку `dist/`

## Notes

- `dist/` должен открываться как статический пакет без интернета
- `node_modules/` и `dist/` игнорируются git
- `.DS_Store` тоже игнорируется
